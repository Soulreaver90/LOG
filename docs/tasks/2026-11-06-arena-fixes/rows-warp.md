| **A map's WARPS live in its LAYOUT, not in its map entry.** `layout +0x40` is the warp COUNT and `layout +0x44` is the warp LIST, a count and list pair exactly like the entry's region count at `+0x03` and region list at `+0x10`. Each word of the list names a warp item whose first word is a factory, `0x0800C233` or `0x0800D9C3`, with `{dir, zone, area, var, x, y}` inline at `+0x10`. Verified over the whole population: **283 layouts where EVERY word of the `+0x44` list is a warp factory record, ZERO where it is not or where the count and list disagree, and 44 layouts with no warp list at all. 283 plus 44 is exactly 327.** Count distribution: 0 x44, 1 x105, 2 x101, 3 x46, 4 x17, 5 x12, 6 x1, 7 x1 | #map | C (whole population, two shapes: the factory word and the destination bytes) | WRP |
| Map 6,1 carries 3 warps at `0x085F2090`, to **`4,6` (West City), `6,21` and `6,2` (the inside of Capsule Corp)**. The 4,6 warp is the item `0x085F2048`, dir 2, var 1, landing (656,368). Map 4,6 carries 3 warps back, to `6,1`, `4,4` and `4,5`. **Map 14,3 and 14,4, the Cell Games arena pair, both carry `+0x40` = 0 and `+0x44` = 0**, so a real arena has no warps at all | #map #combat | C | WRP |
| **A region count of 0 does NOT make a map sealed.** The region list at entry `+0x10` is the only PERFECT separator of maps that have regions, non zero on all 179 and zero on all 148, so the bible row on regions is right. But regions are not the warp carrier. A map copied from another with its layout inherits that layout's warps, and nothing in the map entry shows it. **The arena 6,100 proved this in play: entry region list 0, region count 0, enter script 0, leave script 0, and the swap, pickup and marker lists all 0, yet it warped to 4,6 and the owner returned to 6,1 rather than 6,100, which destroyed the fight.** Controller note: I asserted twice that region count 0 meant no exits. The survey of 327 maps could not see the mechanism, because the mechanism is not in the field I surveyed | #map #debug #decision | C (the owner's save states, read at the current map word `0x03002080`) | WRP |
| **The current map is the byte pair at `0x03002080`**, zone then area. Found by difference across three of the owner's save states on arena v1: state 3 at the start of the fight reads (6,100), state 4 outside the arena reads (4,6), and state 5 on reentry reads (6,1). It is the ONLY byte pair in IWRAM or WRAM that holds (6,100) in state 3 and changes in the other two | #map #debug #tool | C (three states, differential) | WRP |
